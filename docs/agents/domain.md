# Domain Docs

Before exploring the codebase, read the root `GLOSSARY.md` and any decisions in `docs/adr/` relevant to the work. This backend uses a single context. Proceed if either location is absent. The domain-modeling skill creates these documents when terms or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests. If a term is missing, check the codebase's vocabulary and flag genuine gaps for domain modeling.

If a proposal conflicts with an existing ADR, identify the ADR and explain why the decision should be revisited.
